# Analysis

Scripts that turn scenarios and sessions into the figures and tables we present.

- `pnt eval <scenario> --runs N`: Monte Carlo summary
- `pnt results`: regenerates the results table in `systems/verification.md`
- `pnt plot <session.mcap>` (`just plot`): for one estimator in the session (`--estimator`, default the first `/nav/*` topic), writes to `results/<session>/`:
  - `error.png`: horizontal error and HPL over time, fault windows shaded (jamming zones where the truth is near the jammer), alarm flags marked
  - `stanford.png`: HPL against true error with the nominal, misleading, hazardous and unavailable counts (`--alert-limit`, 50 m TBC)
  - `trust.png`: per-source trust over time
  - `time.png`: clock error and ±1σ, only when the estimator estimates the clock
- `python analysis/figures.py --estimator NAME --runs N` (`just figures NAME N`): the four results figures for one estimator, from committed scenarios at seeds 0..N-1 (paired), with the numbers behind them in `summary.md` and `summary.json`. Writes to `results/figures-<estimator>/`:
  - `error_after_gps_loss.png`: error (median, 95th percentile) and HPL against time since GPS loss (REQ-01, T1), on `--outage` (default `realistic-long-outage`)
  - `stanford.png`: HPL against error pooled over `--stanford` (default the `realistic` set) (REQ-02)
  - `ablation.png`: fault-window p95 with all SoOP removed and with each other aid removed (REQ-06)
  - `holdover.png`: clock error and time protection level after GPS loss (REQ-03), when the estimator has a clock
- `accuracy_budget.py`: the UC-01 accuracy budget (REQ-01, T1): each error term after GPS loss from first principles, against the filters run on the same scenarios, and how long GPS must be good first. Writes `results/accuracy-budget/`; the write-up is `systems/accuracy-budget.md` (sim only)
- `rf_survey.py <site>=<power.csv> ...`: the RF survey (#20). Per site, each band's power above the noise floor from an `rtl_power` sweep, as `deploy/pi/rf_survey.sh` records it: `results/rf-survey/summary.md` and `spectrum-<site>.png`. Power only, uncalibrated dB
- `lte_link_synthetic.py`: synthetic baseband through the LTE front end, cell lookup and `ekf`, with and without the dongle clock state (synthetic only)
- `lte_table_audit.py`: every row of the Ottawa cell table through the lookup, from Carleton and a receiver grid: wrong-tower matches, usable geometry, flags (registry only, no radio)
- `lte_real_geometry.py`: the UC-01 circuit on real tower positions, with records shaped as the front end writes them, and wrong tower tables (sim over real positions, not real signals)
- `lte_link_dense.py`: synthetic baseband with every registered cell at a link-budget power: how many cells the front end keeps, and why (synthetic only, TBC link budget)
- `guard_jump_sizes.py --seeds 20 --jobs 3 --out DIR`: GNSS position jumps of 20 m to 500 km held to the end, and clean runs, for `ekf`, `ekf-imu` and their opt-in `-guard` estimators on the UC-01 route (realistic set and as committed): detection, time to alert, hazardous epochs, error after the jump, false alarms (sim only). Writes `summary.md` and `rows.json`
- `guard_manoeuvre.py`: honest GNSS through a hard acceleration or turn on a GNSS-only filter, with and without the opt-in jump guard (ADR-0038): which cases recover GNSS and which the guard keeps out to the end. Prints a Markdown table; `tests/test_jump_guard.py` pins it (sim only)
- `lte_measured_noise.py <session>-lte ... [--raw-root data/sessions]`: LTE pseudorange error on static real captures without truth (#173, ADR-0015): white noise against SNR, the second-difference structure function S(τ) per cell and per pair of cells on one carrier (the pair cancels the dongle), tower-to-tower drift, where broken tracks land, carrier offsets against the strongest cell, the reported σ beside each, and the sim's terms as closed forms of the same statistic. Writes `results/lte-measured-noise/`: `summary.md`/`summary.json`, `white_vs_snr.png`, `structure.png`, `pair_drift.png`, `reacquisition.png`. Precision only: no bias, no multipath size, nothing about motion
- `static_gnss_baro.py <session> [--out DIR]`: GNSS position noise (σ per axis about the mean, lag-1 autocorrelation, 1/e time, reported σ) and barometer noise and drift of a static session, beside the sim's values (ADR-0015, #30). Deviations about the session's own mean only, never a position. Writes `summary.md`, `summary.json` and `static.png`
- `imu_allan.py <session>`: Allan deviation of a static IMU session beside the sim's MPU6050 model, same length and rate (ADR-0015). Writes `results/<session>-allan/`: `allan.png`, and `summary.md`/`summary.json` with each axis's noise density (spectrum, with the Allan slope as a check), Allan floor, static mean and largest spectral peak. Run on a session the Pi recorded still for hours (`deploy/pi/RUNBOOK.md` G)
- `model_mismatch.py`: `ekf` and `ekf-calibrated` paired while the simulated world departs from `ekf-calibrated`'s values (multipath size, correlation time and form, tower clock wander, told tower positions): fault-window p95, worst-run HPL bound rate, NEES, misleading and time-misleading epochs (#118). Reported on seeds 0-49; a change to `CALIBRATED` is tuned on seeds 1000-1049 (sim, placeholder models)
- `lte_static_capture.py <session>-lte`: precision of a static LTE capture, each cell differenced against the strongest on the same dongle (needs two cells)
- `lte_single_cell.py <session>-lte [--plot PNG]`: one cell's own pseudorange split into white noise and slow wander after a quadratic is removed, for captures with one cell. Includes the dongle and tower clocks; precision only, no truth
- `lte_scan_table.py <cu8> ... [--out DIR]`: the cells each LTE capture heard (PCI, seconds tracked, SNR, CFO) and the registered eNB each (EARFCN, PCI) could be in the committed cell table, for #87. Distance from the receiver only with `--receiver-llh`. `--title` names the captures in the heading. Writes `summary.md` and `summary.json` (default `results/lte-scan-20261110/`)
- `antenna_ab_table.py <session> ... [--pair A:B] [--out DIR]`: LTE antenna A/B for #200. The LTE front end on each run's `sdr_a.cu8`: per run the cells tracked, their tracking SNR (marked `floor` near the detection threshold), seconds tracked, arcs, and the capture's RMS and clipped fraction; pairs compared on the cells both tracked. Writes `summary.md`, `summary.json` and `snr_per_run.png` (default `results/antenna-ab-20261110/`)
- `gnss_health_real.py <session>-gnss --out DIR`: `gnss_health` from a real GPS HAT session (#22, ADR-0031), after `pnt frontend gnss <session>`. Statistics only, no positions: record spacing, jamming indicator, mean C/N0 of the strongest satellites (what ADR-0031's open-sky reference is measured from), satellites used, tracked and seen, HDOP. Writes `summary.md`, `summary.json` and `gnss_health.png`
- `iq_impulse_check.py <capture.cu8> [--seconds N --rate R]`: impulsive interference in an RTL-SDR capture, the check before an ADS-B capture (`deploy/pi/RUNBOOK.md` H). Median sample power and the fraction of samples above 10x and 30x it (Gaussian noise: 0.1 % and ~0). Needs only numpy, so it runs on the Pi
- `adsb_avr_capture.py <session> [--plot PNG]`: readsb's AVR frames from a recorded 1090 MHz capture through the ADS-B front end. The frames carry no time: they are spread evenly over the capture, and the script reruns with them squeezed to show whether the result depends on that
- `vor_quality.py <voracious>.jsonl ...`: whether Voracious locked onto a VOR (idents, 30 Hz and 9960 Hz SNR, radial spread), before its radials are used
- `vor_ablation.py --runs 50 --jobs 3 --out results/vor-ablation`: the UC-02 approach with and without its VOR bearings (real stations from `navaids.csv`; only YOW is in range), paired by seed, for `ekf`, `ekf-imu` and `ekf-mhss` (#13, #94): GPS-outage p95, worst run, HPL bound rate, misleading epochs, NEES and the paired change in p95. Writes `summary.md`, `summary.json` and `vor_ablation.png` (sim only, literature error values)
- `pnt compare <simulated> <real> --source lte [--first-s S] [--out fig.png]`: the same residual statistics (size, lag-1 persistence, availability) and histogram from any two sessions (ADR-0015, #30). A channel is one emitter in one tracking arc, its trend removed. Without `/truth`, a static session (`platform: static`) is its own reference, so a real LTE capture with no GPS can be compared
- `pnt replay <session> --inject <scenario or .yaml> [--seed N] [--out folder]`: a scenario's faults applied to a recording, fault times from its first measurement; `--out` saves the injected session for `pnt compare` or `pnt viz`. `inject/` holds fault files sized for real captures
- `jump_refusal.py --seeds 50 --jobs 2`: a GNSS position jump refused instead of followed (#184), sim. `ekf` and `ekf-calibrated` with and without the jump guard, paired, on the challenge drone and timing legs and the many-tower drone case: whether the output follows the jump, error and HPL after it, re-admission after it ends, false alarms, and the alternative re-admission rules. Writes `results/jump-refusal/`: `summary.md`, `runs.json`, `curves.json` and `error_after_jump.png`
- `lte_capture_report.py <session>-lte ... [--out DIR] [--position lat,lon,h]`: one LTE capture or a carrier scan, section by section: cells tracked, identity against the table, reported against observed σ, dongle clock, tower timing, and the `TBC` each number would replace (`deploy/pi/first-capture.md`). Writes `report.md` and figures to a folder outside git by default
- `recite.py [--write]` (`just recite`): after a rebase-merge, finds commits cited in committed results and docs that are not on `origin/main` and re-points each at its twin there, by `git patch-id` (or identical subject and identical diff of the files the citing text names). Dry run by default; lists what it cannot map and the PNGs it leaves alone (`systems/quality.md`, REQ-10)
- `hopping_study.py`: carrier hopping sensitivity sweep (ADR-0040, Proposed): the drone leg's outage error at 120 s and 300 s against masts heard, hopping LTE carriers (`challenge-drone-hop`) and two reference points, as committed and told the true noise; writes `results/hopping-study/` (sim, TBC values). Not the per-term accuracy budget (`accuracy_budget.py`, #178)
- `challenge_baseline.py --seeds 50 --jobs 3`: every estimator on every entry of the three `challenge` legs (ADR-0030, Proposed), the "before" table, with the opt-in jump-guard estimators on the jump, meaconing, `nominal` and `outage` entries: `summary.md` (verdict per target T1 to T5, T1 and its fallback as ADR-0034's across-run p95 at each second after GPS loss; default against guard; full table), three figures and `t1_curves.json` in `results/challenge-baseline/`; per-run metrics and error curves to the git-ignored `results/runs/challenge-baseline/runs.json`, which `--redraw` redraws from (sim; the approach leg is synthetic geometry)
- `spoof_detection.py`: the 2 m/s GNSS position ramp, with a 300 m jump and the time ramp as controls, and false alarms on `nominal` and `outage`, for each estimator against the same one with the opt-in tower monitor (`-spoof`), on the `challenge` drone leg, a many-tower drone case and the `realistic` set (sim, #173). Writes `results/spoof-detection/` (summary and figure) and its per-run rows to the ignored `results/runs/`
- Planned: timing holdover from real sessions. No real session exists yet; `summary.md` keeps a marked placeholder for them

## Viewing a run in Foxglove

1. `pnt sim gps-outage --out data/sessions/demo`
2. `pnt viz data/sessions/demo` writes `data/sessions/demo.viz.mcap`, beside the session folder. It refuses to overwrite an existing file unless you pass `--force`, and never writes into the session folder.
3. Open `demo.viz.mcap` on its own in [Foxglove](https://foxglove.dev) (`Cmd/Ctrl+O`, or drag it in).
4. In the Layouts menu choose **Import from file...** and pick `analysis/foxglove-layout.json`.

The layout shows true (green) and estimated (orange) position on a map with the towers, error against HPL, towers heard, fault and alarm state, and status, flags and lost towers over time. Plots fill in as the file loads. Foxglove is our internal viewer; the operator display is the dashboard (ADR-0010).

The viz file is stamped in Unix time, so the viewer's clock shows the real date and time. The session file stays in GPS time (ADR-0008), which Foxglove would place about 10 years earlier, so don't open the two together: they would not overlap on the timeline.

Takes a session folder or a bare `.mcap`, which needs an `origin_llh`. If the session has no estimates on `/nav/<estimator>` (a real recording, or a sim run with another `--estimator`), `pnt viz` re-runs that estimator over the measurements, as `pnt replay` does. Truth, error and fault state appear only when the session has them.

Rules: every figure's caption names its scenario (or session) and commit (REQ-10). Figures go in `results/`; bulky run data in `results/runs/` (ignored). Images that only back a PR description go in `pr-evidence/<n>/` (`systems/quality.md`).
