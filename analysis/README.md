# Analysis

Scripts that turn scenarios and sessions into the figures and tables we present.

- `pnt eval <scenario> --runs N`: Monte Carlo summary
- `pnt results`: regenerates the results table in `systems/verification.md`
- `pnt plot <session.mcap>` (`just plot`): for one estimator in the session (`--estimator`, default the first `/nav/*` topic), writes to `results/<session>/`:
  - `error.png`: horizontal error and HPL over time, fault windows shaded (jamming zones where the truth is near the jammer), alarm flags marked
  - `stanford.png`: HPL against true error with the nominal, misleading, hazardous and unavailable counts (`--alert-limit`, 50 m TBC)
  - `trust.png`: per-source trust over time
  - `time.png`: clock error and ±1σ, only when the estimator estimates the clock
- `python analysis/figures.py --estimator NAME --runs N` (`just figures NAME N`; `just results` writes them to `results/final/` beside the verification table): the four results figures for one estimator, from committed scenarios at seeds 0..N-1 (paired), with the numbers behind them in `summary.md` and `summary.json`. Writes to `results/figures-<estimator>/`:
  - `error_after_gps_loss.png`: the per-second 95th percentile of the error across runs against time since GPS loss, with T1's and the fallback's worst second (REQ-01, ADR-0034 amendment), median error and HPL, on `--outage` (default `realistic-long-outage`)
  - `stanford.png`: HPL against error pooled over `--stanford` (default the `realistic` set) (REQ-02)
  - `ablation.png`: fault-window p95 with all SoOP removed and with each other aid removed (REQ-06)
  - `holdover.png`: clock error and time protection level after GPS loss (REQ-03), when the estimator has a clock
- `accuracy_budget.py`: the UC-01 accuracy budget (REQ-01, T1): each error term after GPS loss from first principles, against the filters run on the same scenarios, and how long GPS must be good first. Writes `results/accuracy-budget/`; the write-up is `systems/accuracy-budget.md` (sim only)
- `ekf_kernel_bench.py [scenario ...]`: the EKF's compiled covariance kernels against the dense numpy products, per state count, on the filter's own matrices (#255, ADR-0054; run with `OPENBLAS_NUM_THREADS=1`)
- `rf_survey.py <site>=<power.csv> ...`: the RF survey (#20). Per site, each band's power above the noise floor from an `rtl_power` sweep, as `deploy/pi/rf_survey.sh` records it: `results/rf-survey/summary.md` and `spectrum-<site>.png`. Power only, uncalibrated dB
- `lte_link_synthetic.py`: synthetic baseband through the LTE front end, cell lookup and `ekf`, with and without the dongle clock state (synthetic only)
- `lte_table_audit.py`: every row of the Ottawa cell table through the lookup, from Carleton and a receiver grid: wrong-tower matches, usable geometry, flags (registry only, no radio)
- `lte_real_geometry.py`: the UC-01 circuit on real tower positions, with records shaped as the front end writes them, and wrong tower tables (sim over real positions, not real signals)
- `lte_link_dense.py`: synthetic baseband with every registered cell at a link-budget power: how many cells the front end keeps, and why (synthetic only, TBC link budget)
- `guard_jump_sizes.py --seeds 20 --jobs 3 --out DIR`: GNSS position jumps of 20 m to 500 km held to the end, and clean runs, for `ekf`, `ekf-imu` and their opt-in `-guard` estimators on the UC-01 route (realistic set and as committed): detection, time to alert, hazardous epochs, error after the jump, false alarms (sim only). Writes `summary.md` and `rows.json`
- `spoof_sky.py --session DIR --runs 20 --out DIR --plot PNG`: the GPS-sky spoof decision (#206, ADR-0041) on a real session's `gnss_sky` events as recorded (false alarms) and with fake skies injected in software (detection delay), through `ekf-guard` on its fixes, and on `spoof-jump-sky` (sim). Statistics only: the receiver position stays in memory, never printed or plotted
- `guard_manoeuvre.py`: honest GNSS through a hard acceleration or turn on a GNSS-only filter, with and without the opt-in jump guard (ADR-0038): which cases recover GNSS and which the guard keeps out to the end. Prints a Markdown table; `tests/test_jump_guard.py` pins it (sim only)
- `lte_measured_noise.py <session>-lte ... [--raw-root data/sessions]`: LTE pseudorange error on static real captures without truth (#173, ADR-0015): white noise against SNR, the second-difference structure function S(τ) per cell and per pair of cells on one carrier (the pair cancels the dongle), tower-to-tower drift, where broken tracks land, carrier offsets against the strongest cell, the reported σ beside each, and the sim's terms as closed forms of the same statistic. Writes `results/lte-measured-noise/`: `summary.md`/`summary.json`, `white_vs_snr.png`, `structure.png`, `pair_drift.png`, `reacquisition.png`. Precision only: no bias, no multipath size, nothing about motion
- `whiteness.py study|real|hash|compare`: the innovation whiteness test (#275, ADR-0055): window and threshold chosen on sim seeds 0-9 of honest-noise and correlated-error scenarios, reported on seeds 10-29 (runs flagged per source, false-alarm onsets per hour, detection delay); `real` runs `ekf` over whole real sessions (r, T and share flagged per source; statistics only, no position); `hash` hashes every registered estimator's estimates without this test's flags, against any checkout, and `compare` diffs two. Writes `results/whiteness-275/`
- `static_gnss_baro.py <session> [--out DIR]`: GNSS position noise (σ per axis about the mean, lag-1 autocorrelation, 1/e time, reported σ) and barometer noise and drift of a static session, beside the sim's values (ADR-0015, #30). Deviations about the session's own mean only, never a position. Writes `summary.md`, `summary.json` and `static.png`

Writes `results/told-sigma-147/`
- `imu_allan.py <session>`: Allan deviation of a static IMU session beside the sim's MPU6050 model, same length and rate (ADR-0015). - `lte_gps_truth.py <session>-lte [--raw <capture session>] [--out DIR] [--plot PNG]`: LTE pseudorange error of a static capture against GPS truth (#21). Each cell matched in the cell table is differenced against the strongest on its dongle with the true range difference removed: the towers' frame-timing offset, and residual, white noise and S(τ) on epochs where both cells are at or above the SNR cut (−8 dB, ADR-0036), beside the sim and ADR-0036. ## Viewing a run in Foxglove

1. `pnt sim gps-outage --out data/sessions/demo`
2. `pnt viz data/sessions/demo` writes `data/sessions/demo.viz.mcap`, beside the session folder. It refuses to overwrite an existing file unless you pass `--force`, and never writes into the session folder.
3. Open `demo.viz.mcap` on its own in [Foxglove](https://foxglove.dev) (`Cmd/Ctrl+O`, or drag it in).
4. In the Layouts menu choose **Import from file...** and pick `analysis/foxglove-layout.json`.

The layout shows true (green) and estimated (orange) position on a map with the towers, error against HPL, towers heard, fault and alarm state, and status, flags and lost towers over time. Plots fill in as the file loads. Foxglove is our internal viewer; the operator display is the dashboard (ADR-0010).

The viz file is stamped in Unix time, so the viewer's clock shows the real date and time. The session file stays in GPS time (ADR-0008), which Foxglove would place about 10 years earlier, so don't open the two together: they would not overlap on the timeline.

Takes a session folder or a bare `.mcap`, which needs an `origin_llh`. If the session has no estimates on `/nav/<estimator>` (a real recording, or a sim run with another `--estimator`), `pnt viz` re-runs that estimator over the measurements, as `pnt replay` does. Truth, error and fault state appear only when the session has them.

Rules: every figure's caption names its scenario (or session) and commit (REQ-10). Figures go in `results/`; bulky run data in `results/runs/` (ignored). Images that only back a PR description go in `pr-evidence/<n>/` (`systems/quality.md`).
